{# ================================================================ Generic renderer for a module-contributed section (schema.json → __page__). A module that declares no `render` gets this: the core paints whatever its `page_data()` hook returned, so contributing a section costs NO front-end code. A module that wants a different look declares `render` and ships its own web/_ui.html instead — this file is never involved then. The shape it renders (everything module-supplied, nothing hardcoded here): {sections: [{id, name, state, counts:{ok,warn,error,total}, rows: [{name, state, message, metrics:{k: v}, breakdown?}]}], counts: {...}, live: bool, items: [{key, label}]} `breakdown` is optional and is what a row is MADE of: {label, items:[{name, text, pct}], more, note?, page?}. A total answers "how much"; the breakdown answers "of what" — SharePoint's sites, and tomorrow a database's tables or a cluster's nodes. The core reads exactly one number from it, `pct`, which is the same language the ring already speaks; `text` arrives formatted by the module, because bytes-versus-rows-versus-seconds is knowledge the core does not have.
