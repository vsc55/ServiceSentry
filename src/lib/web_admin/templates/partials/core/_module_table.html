{# ================================================================ A module section's `table` VIEW — the generic inventory table. The row/section layout answers "is everything all right"; this one answers "where is it all going". They are different questions about the same subsystem, so they are two views of one section rather than two sections: same pane, same permission, a sub-path apart (see partials/_sidebar.html and lib/modules/discovery/pages.py). The module declares the view in its schema (`"kind": "table", "action": ""`) and answers that action with: {ok: true, columns: [{id, label, kind?, align?, width?}], rows: [{colId: value, …}], message?} `kind` is 'text' (default), 'num' or 'pct'. A value is either a scalar — shown and sorted as it is — or `{v, s}`: `v` sorts and `s` is shown, which is how "3.0 TB" can sort as 3298534883328 without the core knowing what a byte is. The module formats, because bytes-versus-rows-versus-seconds is knowledge the core does not have; the core lays out, sorts, filters, paginates and remembers the column choice, which is knowledge the module should never have to acquire. Declaring an `action` makes the view LIVE: it asks when opened and keeps nothing.
