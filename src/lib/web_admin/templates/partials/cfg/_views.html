{# ================================================================ Configuration — an index down the side, one section beside it. Seven sub-tabs held twenty-seven cards, and they answered exactly one question well: "show me the settings about X". Finding a setting meant opening seven of them, and they said nothing about the six you were not looking at — least of all which ones this install had actually changed. The index replaces them outright. It is not a view among others: a second navigator over the same cards would be one more thing to keep in step with this one, for a question this one already answers. So there is no view registry and no switcher — this IS the section. It is a PASS over the DOM `renderConfig()` produced, exactly like the search filter has always been. No second renderer, no second copy of the field vocabulary, and every field keeps the wiring it was born with. Cards are shown and hidden, never rebuilt, so switching section keeps handlers, tooltips and half-typed values; and every card stays in the DOM, so the search still has all of them to search. `data-cfg-path` is what lets the index count: a rendered field knows its own `section|field`, so its value can be compared against CONFIG_REGISTRY_DEFAULTS and the index can say WHERE this install departs from stock before anything is opened.
