{# ================================================================ Syslog — the part every view shares. This is the one section whose rows arrive already filtered, sorted and paged BY THE SERVER: the table you see is one page of a query, not a slice of something the browser holds. So the views here differ only in how that page is drawn, and every one of them keeps the pager — it is the control that loads more, not a presentation trick. Two shapes the table cannot be: * a STREAM. Reading a log in a grid means re-reading five column headers per line to follow one machine's story; a console line puts the severity, the clock, the host and the text where the eye already expects them, and fits twice as many lines on screen. Logs are read, not compared, and this is the shape reading wants. * PATTERNS. Five hundred lines are usually a dozen distinct messages repeated, and the one that matters is often the one that appears twice. Collapsing by "the same message with different numbers in it" turns a wall into a list you can finish, and puts the rare line where you can see it. Patterns describes what is LOADED, and says so on screen: the store can hold millions of rows and the browser has one page of them. A count that silently meant "of the last 50" would be worse than no count — so the header states it, and the page-size control (up to "all") is how you widen what it covers. ================================================================ #} // ── The registry ───────────────────────────────────────────────────────────── // `render` is looked up by NAME at call time: the view files are concatenated after this // one.
