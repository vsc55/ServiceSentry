{# Account settings as its own page (served at /account, standalone='account'). Personal preferences (language + landing page) and security (change password + the second factor). Dark mode is NOT here — it is the quick toggle in the user menu (see _sidebar.html). Fields are populated by initAccountPage() and saved by saveAccountPreferences() (both in partials/account/_render.html). THE SHELL. Same one Configuration and Modules use: an index down the side, level with the toolbar and running to the bottom of the pane, and the open section beside it filling everything left. Full-bleed on all four edges, because a navigation column is part of the frame and a strip of page background around it reads as the panel having failed to fill. Three layouts were tried before this one, and the two that lost are worth naming so they are not tried again: a single centred column (the second factor pushed the security half below the fold), and a boxed 640px card stack with tabs — centred in a wide screen, it left more empty page than page, and the tab bar sat where the section title goes. No title of its own either: the breadcrumb in the top bar already names the section, and an
in the toolbar printed "Configuración de Cuenta" twice on the same screen. #}
{# The index. `ss-rail-item`, not a Bootstrap pill: this is the panel's own index and it has to look the same here as it does in Configuration. Switching is `_accSection()` rather than `data-bs-toggle` — the rail is not a `.nav`, and a Bootstrap tab that cannot find its parent list fails by doing nothing at all. #}
{# Reload and Save belong to the top edge, over the detail — the same pair, in the same place, that Configuration keeps. Below the cards they were two buttons floating in the middle of a wide empty page. RELOAD and not Cancel. There is nothing to cancel: this page opens with what the server already holds and writes nothing until Save. "Cancel" meant "go back", which is what the browser's own Back button is for, and it read as "undo" — the one thing it did not do. Reload is the honest version of the same gesture: throw away what is typed and ask the server again. SAVE IS DISABLED UNTIL SOMETHING CHANGES, with the same dirty badge Configuration uses. A button that is always available says nothing about whether there is anything to do, and on a page whose other half is a password form, "did I change something?" is a question worth answering on the button itself. #}
{# One Save for both sections: it writes whatever was filled in — language, landing page, password — and the section that is not on screen keeps its fields in the DOM, so switching never drops an edit. #}
{# A grid, not a column: on a wide screen the cards of a section sit side by side instead of one narrow strip down the left with the rest of the page empty. Below `xl` they stack, which is the only thing a card of form fields can do on a narrow screen. #}
