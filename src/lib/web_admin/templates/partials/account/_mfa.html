{# ================================================================ Account — the second factor: setting one up, turning it off, and the recovery codes. Two ways to enrol are always drawn: the QR, which is what anybody actually uses, and the base32 key beside it. The key is the half somebody can read back and check, and the only one left when the camera will not focus, the phone has no camera, or the square came out wrong — which is a possibility this project takes seriously, because the QR encoder is written here and no test can hold a phone up to a screen. ================================================================ #} /** What the server says about this account's second factor. ${esc(t('loading'))}
`; } // `apiGet` answers the parsed BODY; `apiPost`/`apiDelete` answer `{status, data}`. Two // shapes in one module, and reading the wrong one here did not fail loudly — it fell to // the default, so an account with a factor was drawn as "not set up" and the button then // POSTed an enrolment the server correctly refused with 409. ${esc(t('mfa_desc'))}

${esc(t('mfa_desc'))}
${ esc(t('mfa_recovery_left').replace('{}', _accMfa.recovery_left))}
`; } /** Start an enrolment and show both ways in. * * The secret is drawn from what the server just stored, so the square and the string are * the SAME secret the confirmation will verify — building the URI in the browser would be a * second place that decides what is being enrolled. */ async function _accMfaBegin(ev) { // Minting a secret and drawing a QR is the longest wait in this card, and it happens with // NOTHING on screen yet — the dialog only appears once the answer is in. ${d.svg}

${esc(t('mfa_enrol_no_qr'))}

${esc(d.secret_groups || d.secret || '')}
${esc(t('mfa_enrol_confirm'))}
`, 'primary', ``); _accMfaWireCode('accMfaCode', _accMfaConfirm); } /** The code field: Enter submits it, and it has the cursor when the dialog opens. * * Both are the same observation — this dialog exists to receive six digits, so the six digits * are what it should be ready for. Enter needs saying out loud because there is no `
` * here: a lone input outside one does nothing at all on Enter, which is a keypress that looks * ignored rather than unsupported. * * The focus goes through `shown.bs.modal` when the dialog is opening — focusing an element * Bootstrap has not finished showing is focus that Bootstrap then takes back — and directly * when the box is already up, which is the regenerate path replacing the contents of a dialog * that never closed. */ function _accMfaWireCode(id, run) { const el = document.getElementById(id); if (!el) return; el.addEventListener('keydown', e => { if (e.key !== 'Enter') return; e.preventDefault(); run(); }); // Typing clears the last refusal. This one only raises a toast, and left alone it sat there asking // for a code that had already been accepted. hideInfoModal(); showToast(t('mfa_disabled_ok'), 'success'); _accMfaLoad(); }); }
