{# ================================================================ Infrastructure — asking a device for fresh numbers, and watching it happen. The section draws what the last cycle RECORDED. How old that is depends on the scheduler interval, and for a device sampled by a full SNMP profile on the minutes the sampling itself takes — a Synology answers about a thousand values and takes roughly five. Somebody who has just replaced a disk should not have to wait for a tick, and the only way to ask used to be the Status screen's "run all": every module, every machine. THREE THINGS THIS FILE IS ABOUT, and they are all the same complaint: * a run that shows nothing until it ends is indistinguishable from one that has hung, so there is a dialog that says WHICH module is working; * nothing about the run depends on somebody watching it — the work is a thread on the server, so the dialog closes and the collection carries on; * and once it is closed there is still a bar with a percentage, because "is it still going?" must be answerable without reopening anything. Its own partial, and not the section shell: the shell is the entry point, the state and the machine view, and this is a self-contained story with a dialog, a poll and a bar. ================================================================ #} //: The collection this browser started, while it is still going. `null` the rest of the time. //: One at a time is not a decision made here — the server holds the same lock the Status //: screen's run takes, so a second attempt is refused with a message rather than queued. let _infraCollectJob = null; // {id, host, host_name, total, completed, modules[], done…} //: Whether the shared dialog is currently showing THIS. `; }
