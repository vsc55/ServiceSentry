{# ================================================================ Infrastructure — the two network maps, laid out so that they still read at three hundred machines. Both maps were drawn as one long picture of the whole fleet: the address map as a tree that came out as a single horizontal line with a fan of curves, the cable map as columns of breadth-first tiers that came out as a strip one box wide and three hundred tall. With the demo's 356 devices neither showed anything — the data was right and the layout did not scale. Reported from the screen with both pictures. What a person reading a network diagram asks first is WHERE: which building, which room. The inventory already knows it (an item bound to a device sits in a rack, in a room, in a site — `infra.service.places`), so both maps are now drawn as SITES: * **a site is a frame** with its machines inside, arranged in BANDS: by role on the cable map (edge → core → access → servers → endpoints, which is how a network is drawn by hand), by network on the address map (the plate a machine hangs from is the band it is in, so membership is containment and not a fan of three hundred lines); * **a site can be folded** into one box with its count and its worst state, and the lines to a folded site are added up into one with the number on it. A large fleet starts folded (`_NG.AUTO`), so what opens is six sites with a red one among them rather than a picture of nothing; what somebody folds or unfolds is kept per map on their account (the list's table configuration, beside the view it remembers). * **the sites are placed in two dimensions**: a few hundred rounds of springs on the BLOCKS (connected sites pull together, all of them push apart), then their rectangles are pushed out of each other. On blocks, never on machines: a spring layout of three hundred boxes is the hairball the cable map was written not to draw, and it is O(n²) per round. Everything here is a pure function of what it is given — no DOM, no state — so it is the part the tests run in `node`, with a synthetic thousand-machine fleet and a time budget. What is drawn, and what a press on it does, stays with each map. ================================================================ #} //: Geometry of the clustered layout. One order for machines, folded sites and lines: a link //: that is DOWN is worse news than a machine in error, which is worse than a degraded trunk. const _NG_RANK = {down: 6, error: 5, degraded: 4, warning: 3, maintenance: 2, ok: 1, '': 0}; function ssNetWorst(states) { let best = ''; for (const s of states || []) { const k = String(s || ''); if ((_NG_RANK[k] || 0) > (_NG_RANK[best] || 0)) best = k; } return best; } /** The first part of a location a device declares about itself (sysLocation), which is the * site in every way people write one: `Madrid › CPD › R-04`, `Madrid > CPD`, `Madrid, planta 2`. * Only for a machine the inventory does not place — and named as what it is when drawn. */ function ssNetLocationHead(text) { const head = String(text || '').split(/\s*(?:\u203a|\u00bb|>|\||;|,|\/)\s*/)[0].trim(); return head.length > 48 ?
