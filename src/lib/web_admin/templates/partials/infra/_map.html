{# ================================================================ Infrastructure — who can reach whom, drawn. Every line here is INFERRED, and the drawing has to keep saying so. What the panel knows is which addresses each machine claims, which network each of those sits on, and where each machine sends what it cannot deliver itself. From that: two machines on one network can reach each other, and a machine points at its way out. Which port is plugged into which port is a different question with a map of its own — see `_links.html` — and it is not duplicated here: two pictures of the same cable are two things to keep in agreement. IT IS A TREE, READ DOWNWARDS: what is outside, the way out, the networks, then what is on them. That is how everybody reads a network diagram and it was right the first time — what was wrong was everything around it. Thirty networks meant thirty columns, and the whole picture was then squashed into whatever width the pane happened to have, so the more the fleet had the smaller every name got. Reported from the screen: *"eso es inusable"*. Three things fixed that, and none of them is the shape: * it is drawn on the shared canvas (`_canvas.html`), so it is a WINDOW — wide is fine now, because you can zoom and push it around instead of being shown all of it at four pixels; * the columns that were not worth one are gone (below); * and the boxes can be dragged where the room actually is, which is the only thing that makes a generated layout somebody else's rack. Two rules do most of the work: * **A network with one machine on it is not a place where two machines meet.** Docker gives every host a 172.17.0.0/16; a router declares a route per VLAN. Those were half the lanes on the old picture and none of them answered the question it exists to answer. They are folded onto the machine that holds them, counted and named on the hover. * **A network nobody is on is not on the map at all** — it is a route, and it belongs in a sentence under the picture rather than as a lane the eye has to skip.
