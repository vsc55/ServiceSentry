{# Permissions section — assigning permissions to roles on a full page instead of one role at a time inside the role modal. Why it exists: the modal shows ONE role, as an accordion over 17 groups and 64 permissions. "Does support have everything editor has?" means opening two modals and remembering the first — the question that matters most when handing out access is the one the UI could not answer. Two layouts ship together so they can be compared on real data (matrix = permissions × roles, split = one role at a time next to the role list). Both read the same draft and write through the SAME endpoint the role modal uses (PUT /api/v1/roles/), so this is a second *view*, never a second way to persist. The role modal keeps its own Permissions tab for now — this section is additive. The chrome is the SAME component every list section uses — the .ss-card + .ss-accent + .ss-card-header that createListTable emits — and NOT a .ss-toolbar: inside a full-bleed pane a card goes flush automatically, while a toolbar keeps its border, its rounded corners and its gap, which made this section read as a card floating in a pane that has no margins, unlike Users or Roles right beside it. #}
