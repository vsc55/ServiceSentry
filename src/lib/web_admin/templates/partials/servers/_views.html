{# ================================================================ Servers — the part every view shares. The host registry is the one list where the rows are not the point: what you actually want from it is a state of the fleet, and the table gives you that one host at a time. Three questions it leaves on the floor: * how is the fleet RIGHT NOW. There is a status column and you can sort by it, which answers "which is the worst host" and never "how many are broken". Grouped by state the answer is the first thing on screen, and an empty error group is itself the good news. * which hosts are not actually being MONITORED. A host with no checks is registered and watched by nothing; a host whose checks are all disabled is worse, because somebody turned them off and the row still looks configured. Both read as ordinary rows in the table — the modules column says "0/0" and "0/3" in the same grey pill — and both mean the fleet is smaller than the list suggests. * what a host IS, as one object rather than a row of columns: its address, kind, OS, tags, clusters and check count together. That is the card view. The last two are SUMMARIES: they are handed everything the filters left standing rather than the page on screen, and they draw no pagination — a count over one page changes as you page through it, which is worse than not counting. What must NOT differ between views is what a host means: the status vocabulary, the maintenance override that wins over it, and the ACTIONS.
